# Advertising artwork attachments

Checkout shows one file input and click-through HTTPS URL for every selected slot, including bundles. The selected publisher website is read-only context, distinct from each advertiser destination URL. Image slots accept JPEG/PNG/GIF/WebP; video-ad slots require MP4. Maximum size is 20 MiB per file. Browser uploads the actual File bytes, with server-side bounded reading, signature/type checks, rate limits and member ownership checks. Order creation requires exact slot coverage and stores immutable attachment metadata in quote JSON. Staff can download each file from the order manager; downloads require the owner or MANAGER+ and use attachment disposition and no-store headers.

Storage is private local disk. Development uses ignored `.local-ads-uploads`; production requires absolute `ADS_UPLOAD_DIR` on a persistent shared volume. Do not use ephemeral/serverless disk or separate unshared disks across instances. Without configuration production uploads fail closed. This is not an R2 integration. Include this directory in backup/restore alongside the DB. Signature checking is not antivirus scanning. Unsubmitted uploads currently remain retained; operators need retention/quota/cleanup policy before public launch, and must never remove files referenced by orders.

No new schema migration; existing order/account migrations remain prerequisites. Existing orders and media are unchanged. New submissions must include attachments. Disable checkout while rolling back to older code that cannot display attachments; preserve files and quote snapshots. No media workers changed, so worker draining is not required. Canary upload/download and staff review with a non-production order before enabling sales. No production deployment, remote storage mutation or real payment was performed.
